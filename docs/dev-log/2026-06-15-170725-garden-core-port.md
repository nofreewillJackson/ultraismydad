## Port shape

Legacy modules ported close to verbatim:
- `src/lib/garden/render.ts` → `src/render/garden-markdown.ts`
- `src/lib/garden/plugins.ts` → `src/render/garden-plugins.ts`
- `escapeHtml` from `src/lib/format.ts` → `src/render/escape.ts`

Legacy `garden/index.ts` was **not** ported as a god-module. Its concerns were re-seated:
- `src/domain/garden-note.ts` owns note defaults, slug/index helpers, wikilink resolution, and backlink
  derivation.
- `src/store/filesystem-garden-note-store.ts` reads markdown/frontmatter and reconstitutes notes
  through `createGardenNote`.
- `src/app/garden-note-pages.ts` calls `exportReadModel`, builds the resolver from **public notes
  only**, renders markdown, derives backlinks, and sorts by recency.
- `src/render/garden-index.ts` and `src/render/garden-note-detail.ts` render the public views.
- `src/pages/garden/index.astro` and `src/pages/garden/[slug].astro` are thin Astro glue.

Privacy decision:
- `GardenNote` carries unified `visibility`.
- Missing visibility defaults to `private`.
- Legacy `draft` frontmatter is treated as migration input only (`draft: true` → private,
  `draft: false` → public), but public content was migrated to explicit `visibility: "public"`.
- `exportReadModel` gates garden notes with the same `selectPublic` used for work items and log
  entries.
